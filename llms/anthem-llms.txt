# Anthem (Elevance Health)

> Anthem, operating under Elevance Health, is one of the largest US health benefits companies, serving members through affiliated Blue Cross and Blue Shield plans. Its public API surface exists to satisfy the CMS Interoperability and Patient Access Final Rule (CMS-9115-F): three HL7 FHIR APIs — Patient Access, Provider Directory and Drug Formulary — plus a live SMART-on-FHIR member server, Patient360. There is no commercial API product, no pricing, no SDK and no MCP server.

Generated by the API Evangelist enrichment pipeline on 2026-09-02 from Anthem's own published surface. Anthem does not publish an llms.txt of its own (https://www.anthem.com/llms.txt returned 404 on 2026-09-02).

## APIs

- Provider Directory API — FHIR R4 4.0.1, Da Vinci PDEX Plan Net 1.1.0, US Core STU 3.1.1. Base `https://totalview.healthos.elevancehealth.com/resources/unregistered/api/v1/fhir/cms_mandate/mcd/`. Resources: Practitioner, PractitionerRole, Organization, OrganizationAffiliation, Location, HealthcareService, InsurancePlan, Specimen. The capability statement at `<base>/metadata` is served anonymously (HTTP 200); the data paths are not.
- Drug Formulary API — FHIR R4, Da Vinci PDEX US Drug Formulary IG 2.0.1 STU2. Base `https://totalview.healthos.elevancehealth.com/resources/unregistered/api/v1/fhir/cms_mandate/frmlry`. Resources: InsurancePlan, Basic (FormularyItem), MedicationKnowledge (FormularyDrug). Medicare, Medicaid and CHIP plans. `/metadata` returns 403 anonymously.
- Patient Access API — FHIR R4 4.0.1, CARIN IG for Blue Button STU 2.1.0, US Core 6.1.0, SMART App Launch 2.2.0. Five years of medical, dental, vision, pharmacy claims and clinical data. Thirteen brand-specific production bases under `https://totalview.healthos.elevancehealth.com/resources/registered/<Brand>/api/v1/fhir` (Amerigroup, Anthem Blue Cross, Anthem Blue Cross Blue Shield, Blue Medicare Advantage, Clear Health Alliance, Dell Children Health Plan, Healthy Blue, Healthy Blue Blue Choice, Healthy Blue NC, Simply HealthCare, Summit, Unicare, Wellpoint). Requires member consent; token valid 90 days.
- Patient360 member FHIR — FHIR DSTU2 1.0.2, SMART on FHIR, CareEvolution HIEBus 32.11.4. Base `https://patient360c.anthem.com/P360Member/api/fhir`. 32 resources. Live and anonymously discoverable via `/metadata`.

## Authorization

- Patient Access uses SMART on FHIR authorization_code with member consent. Provider Directory and Formulary use OAuth 2.0 client_credentials; the token endpoint URL, client id and client secret are sent to each approved developer by secure email and are not published.
- [OpenID Connect / SMART discovery (Patient360)](https://patient360c.anthem.com/P360Member/identityserver/.well-known/openid-configuration): 1,048 scopes, PKCE S256, RS256 id tokens.
- Scope grammar: `patient|user|system / <FHIR resource> . read|*`, plus `launch/patient` and the OpenID Connect set.

## What Anthem does not publish

- No OpenAPI or Swagger document. The machine-readable contracts are FHIR CapabilityStatements at `/metadata`.
- No client SDK in any language. The only first-party packages are the dormant Nimbus framework on Maven Central under `com.antheminc.oss`, last released 2019-08-22.
- No MCP server, no agent card, no llms.txt, no `/.well-known/` document at any host root.
- No changelog, no status page, no SLA, no deprecation policy, no published rate limits, no error reference, no pricing.

## Known behaviour worth encoding before you call it

- Every anonymous request to a Provider Directory data path returns HTTP 500 with `{"status_code":500,"status":"failed","error":"Internal server error","error_description":"An unexpected error occurred. Please try again"}` — including requests for resource types and ids that do not exist. It is not a 401 and not a FHIR OperationOutcome. Do not treat it as transient and do not retry it without credentials.
- Responses carry no request id, no correlation id and no rate-limit headers.
